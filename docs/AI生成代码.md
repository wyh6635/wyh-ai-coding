# AI代码生成指导文档

> **写给完全不懂编程的你：**
> 
> 如果你从来没有写过代码，不知道什么是"前端"、"后端"、"数据库"，完全没关系！这份文档就是为你准备的。
> 
> 在AI时代，写代码不再需要记住复杂的语法规则。你只需要**用平常说话的方式**告诉AI你想做什么，AI就会帮你把代码写好。就像你告诉外卖APP"我要一份宫保鸡丁"，厨师就会帮你做出来一样简单。
> 
> 本文档将手把手教你：
> - 如何用"大白话"描述你想要的功能
> - 如何让AI帮你生成完整的代码
> - 如何运行和测试AI写好的代码
> - 遇到问题时如何让AI帮你修改
> 
> 你不需要懂任何编程语言，只要会打字、会描述需求，就能体验"vibe coding"（氛围感编程）的乐趣。让我们一起开始吧！

## 一、简易版

### 1.1 核心思路

**用自然语言描述你想要的功能，AI帮你写代码。**

你不需要懂编程语法，只需要清楚地告诉AI：
- 你想要做什么功能
- 这个功能在哪个页面
- 用户怎么操作
- 期望看到什么结果

### 1.2 操作步骤

#### 第一步：明确需求

在找AI生成代码前，先自己想清楚：
- 这个系统的名叫什么名字？（例如：学生管理系统）
- 这个系统主要的功能有哪些？
- 用户怎么使用？（例如：输入学号，点击查询，显示结果）
- 需要什么数据？（例如：学号、姓名、班级、状态）
说明：
- 如果只是有个初步想法，可以把想法在豆包、DS上对这个想法做功能清单梳理。

#### 第二步：向AI发送提示词生成系统

**示例：**
```
【角色】你是一个有10年以上全栈开发工程师，精通Python，FastAPI+Vue3+MySQL。
【任务】帮我写一个校园信息管理系统，包括学员管理、班级管理、系统公告管理、科目管理、成绩管理、数据看板和个人信息等模块。
【约束】
    1.技术栈使用Python3、FastAPI、Vue3、Element Plus、Axios、MySQL 8.0+数据库，且前后端进行分离。
    2.后端代码要符合PEP8规范，注释要详细，前端代码要符合Vue3规范。
    3.要实现登录功能，且要用验证码进行校验。
    4.数据库表要符合MySQL设计规范，字段要符合MySQL数据类型。
    5.有修改的页面，要做必要性校验。
    
【输出】
    1.按软件开发流程，生成PRD、详细设计文档、接口文档，Markdown格式的文档，并保存到项目根目录docs下。
    2.按文件路径输出完整代码：docs/init.sql、后端所有py文件、前端所有vue/js/json文件。
    3.生成前后端启动脚本，并保存到项目根目录下。
```
**注：** 使用阿里的TraeCode工具，在项目当前文件目录下，将提示词复制到对话框中，结合Builder模式，即可生成代码。目前写代码是免费使用token，偶尔有排队情况。各自根据实际情况调整。

#### 第三步：运行和测试

AI生成代码后：
1. 按照AI提供的启动命令运行前后端项目
2. 打开浏览器访问对应页面
3. 测试每个功能是否正常工作
4. 如果有问题，告诉AI哪里不对，让它修改

### 1.3 常见场景示例

#### 场景1：新增一个页面功能

```
我想在系统中新增一个"班级管理"功能：
- 页面路径：/class-manage
- 功能：班级的增删改查
- 字段：班级编号、班级名称、班主任、人数、状态
- 要求：班级编号唯一，删除时如果班级下有学员则不允许删除
```

#### 场景2：修改现有功能

```
学员列表页面需要修改：
1. 表格增加"入学日期"列
2. 搜索条件增加"入学日期范围"筛选
3. 新增学员时，入学日期默认当天
```

#### 场景3：修复Bug

```
现在有个问题：删除学员时，即使该学员没有成绩记录，也提示"该学员有关联成绩，无法删除"
请帮我检查并修复这个问题。
```

### 1.4 注意事项

- **一次只做一个功能**：不要一次性让AI做太多功能，容易出错或需反复修改
- **描述要具体**：越详细越好，包括字段名、按钮文字、提示信息等
- **及时反馈**：运行后有问题马上告诉AI，让它调整
- **保存好代码**：AI生成的代码要及时保存到对应文件
- **AI多开任务**：不要一个任务耗时过长，可以多开一个任务，避免幻觉问题及其它异常情况
- **及时复核**：运行后，检查代码是否正确，并确保功能正常

## 二、按开发流程逐步迭代

### 2.1 标准开发流程

按照软件工程规范，分步骤让AI生成代码，每步生成对应的文档并保存到 `docs/` 目录：

#### 开发流程图

```mermaid
flowchart LR
    A[第1步：需求说明书] --> B[第2步：UX交互设计]
    B --> C[第3步：PRD规格说明书]
    C --> D[第4步：数据库设计]
    D --> E[第5步：接口设计]
    E --> F[第6步：测试数据脚本]
```

#### 第1步：需求功能清单

**提示词示例：**
```
你是校园信息管理系统的产品经理。设计一份标准的功能清单 Markdown，文件为"docs/功能需求清单.md"，模块包括：用户管理（分管理员、教师、学生角色并规定权限）、班级管理、科目管理、成绩管理和系统公告管理。要求符合标准软件工程需求分析规范。
```
**保存文件：** `docs/功能需求清单.md`

#### 第2步：UI设计（原型交互设计文档）

**提示词示例：**
```
你是有10年以上经验的UI设计师。请设计一个"校园信息管理系统"的后台主界面交互原型图 Markdown。要求包含左侧垂直导航菜单（用户、班级、成绩、公告等功能模块）和右侧工作区视图，并列出主要的交互跳转逻辑。
```
**保存文件：** `docs/frontend-ui.md`（交互设计文档）

#### 第3步：软件需求规格说明书（PRD文档）

**提示词示例：**
```
请帮我为"校园信息管理系统"编写一个简版的 PRD 需求规格说明书框架。要求明确接口的非功能性需求，并规定必须支持 CORS 跨域免检和 Token 安全验证。要符合标准软件需求规格说明书。文件为 "docs/PRD.md"
```
**保存文件：** `docs/PRD.md`（软件需求规格说明书）

#### 第4步：数据库设计文档

**提示词示例：**
```
你是一个有10年以上经验的DBA专家。根据"校园信息管理系统"的功能清单及PRD文档，请编写数据库设计文档，并保存为 "docs/数据库设计文档.md"，包含数据库表结构、索引、约束、初始数据设计描述及初始数据脚本，要求符合MySQL设计规范。
```
**保存文件：** `docs/数据库设计文档.md`（含 init.sql）

#### 第5步：设计前后端分离交互接口规范

**提示词示例：**
```
你是一个有10年以上经验的全栈开发。请为"校园信息管理系统"的用户管理模块，设计标准的前后端分离 RESTful API 接口定义。使用 JSON 格式，请求 Body 示例和统一的 code/msg/data 响应格式。文件为 "docs/接口设计文档.md"
```
**保存文件：** `docs/接口设计文档.md`

#### 第6步：编写测试数据 SQL 及初始化脚本

**提示词示例：**
```
请编写一个 Python 执行 init.sql 初始化的脚本，并连接数据库进行初始化数据。
```

### 2.2 文档整理与任务清单生成

#### 整理文档到项目目录

将上述所有生成的文档统一保存到项目的 `docs/` 目录下：

```
school_manager/
└── docs/                    # 文档目录
    ├── README.md            # 文档索引说明
    ├── 功能需求清单.md       # 需求说明书
    ├── frontend-ux.md       # 交互设计文档
    ├── PRD.md               # 软件需求规格说明书
    ├── 数据库设计文档.md     # 数据库设计（含init.sql）
    ├── 接口设计文档.md       # 前后端接口规范
    └── 测试脚本.md          # 执行测试数据的脚本
```

#### 生成TODO任务清单

将 `docs/` 目录下的所有文档内容提供给AI，让AI输出分阶段的任务清单：

**提示词示例：**
```
以下是我项目的完整文档：
（粘贴 docs/ 目录下所有文档内容）

请帮我输出一份分阶段的开发任务清单 Markdown，要求：
1. 按开发阶段划分（如：阶段1-环境搭建、阶段2-用户管理、阶段3-班级管理等）
2. 每个阶段明确：前置条件、开发内容、验收标准
3. 标注前后端开发顺序
4. 输出为 docs/任务清单.md
```

### 2.3 按任务清单分阶段逐步开发

从阶段1开始，按任务清单逐项实施：

#### 开发步骤

1. **查看当前阶段任务**：打开 `docs/任务清单.md`，确认当前要开发的阶段
2. **按任务生成代码**：将当前阶段的需求告诉AI，生成对应代码，例如：请帮忙实施阶段一的功能
3. **验证功能**：运行代码，测试功能是否正常
4. **标记完成**：在任务清单中标记已完成的任务
5. **进入下一阶段**：重复上述步骤

#### 示例：阶段1开发

```
当前任务：阶段1 - 环境搭建及用户管理模块

请帮我实现：
1. 创建项目基础结构（前后端分离）
2. 配置数据库连接
3. 实现用户登录接口
4. 实现用户列表查询接口
5. 生成前端登录页面

技术栈：Python3 + FastAPI + Vue3 + Element Plus + MySQL 8.0+
```

**注：**只需要查看TODO任务清单，用自然语言描述操作步骤即可（无需把每阶段所有内容喂给AI），让AI生成代码

### 2.4 高效提问技巧

#### 技巧1：提供上下文

```
当前项目是校园信息管理系统，技术栈：
- 后端：FastAPI + MySQL + PyMySQL
- 前端：Vue 3 + Element Plus + Axios

现在需要在学员管理模块增加"批量导入"功能：
1. 前端提供Excel上传按钮
2. 后端解析Excel，批量插入学员数据
3. 导入失败时返回具体错误信息（哪一行，什么错误）
4. 支持模板下载

请给出前后端完整实现代码。
```

#### 技巧2：指定技术实现方式

```
帮我实现成绩统计接口，要求：
- 使用原生SQL查询（不用ORM）
- 返回每个科目的平均分、最高分、最低分、及格率
- 按平均分降序排列
- 接口路径：GET /api/scores/statistics
- 需要JWT鉴权

请按照项目现有的代码风格实现，参考 scores.py 的写法。
```

#### 技巧3：分步骤生成

对于复杂功能，可以分步骤让AI生成：

```
第一步：帮我设计数据库表结构（SQL语句）
第二步：根据表结构生成后端CRUD接口
第三步：生成前端页面和组件
第四步：联调测试，修复问题
```

### 2.5 代码审查要点

AI生成代码后，检查以下几点：

#### 后端检查清单
- [ ] 接口路径是否符合RESTful规范
- [ ] 是否有参数校验（必填项、数据类型、长度限制）
- [ ] 是否有权限控制（管理员/学员角色）
- [ ] 数据库操作是否有异常处理
- [ ] 返回格式是否统一（参考项目现有的 response.py）
- [ ] SQL是否有注入风险（使用参数化查询）

#### 前端检查清单
- [ ] 页面路由是否正确配置
- [ ] 接口调用路径是否正确
- [ ] 表单是否有校验规则
- [ ] 加载状态、空状态、错误状态是否处理
- [ ] 按钮权限控制（如：学员角色看不到删除按钮）
- [ ] 分页、搜索条件是否正确传递

### 2.6 调试技巧

#### 后端调试
```bash
# 查看后端日志
tail -f backend/app.log

# 常见错误排查
- 500错误：查看后端日志，通常是代码逻辑或数据库问题
- 401错误：未登录或Token过期
- 403错误：没有权限
- 404错误：接口路径不对
```

#### 前端调试
```
打开浏览器开发者工具（F12）：
1. Console：查看JavaScript错误
2. Network：查看接口请求和响应
3. 常见问题：
   - 接口报404：检查api文件中的路径是否正确
   - 数据不显示：检查返回数据格式是否匹配
   - 按钮点击无反应：检查事件绑定和方法定义
```

### 2.7 最佳实践

#### 1. 利用PRD文档
项目 `docs/` 目录下有完整的需求文档，生成代码前可以先看对应模块的PRD，然后告诉AI：

```
请参考 docs/PRD.md 的需求文档，实现学员管理功能。
```

#### 2. 参考现有代码
让AI参考项目已有的代码风格：

```
请参考 backend/routers/students.py 的代码风格和结构，
实现科目管理模块的接口。
```

#### 3. 版本控制
每次AI生成代码并验证通过后，建议提交代码：

```bash
git add .
git commit -m "feat: 完成学员管理模块"
```

这样如果后续改坏了，可以回退。

#### 4. 测试验证
生成代码后，务必测试以下场景：
- 正常流程（ happy path ）
- 边界情况（空数据、超长文本、特殊字符）
- 异常流程（网络错误、数据库断开、权限不足）

### 2.8 常见问题FAQ

**Q1：AI生成的代码运行报错怎么办？**
A：把错误信息完整复制给AI，它会帮你定位和修复。

**Q2：前后端接口对不上怎么办？**
A：检查以下几点：
- 接口路径是否一致
- 请求方法是否一致（GET/POST/PUT/DELETE）
- 参数名称和格式是否匹配
- 使用浏览器Network面板查看实际请求

**Q3：AI生成的代码和现有代码风格不一致？**
A：在提示词中明确要求：
```
请严格按照项目现有代码风格实现，包括：
- 变量命名方式
- 错误处理方式
- 返回数据格式
- 注释风格
```

**Q4：如何保证生成代码的质量？**
A：
1. 提供详细的上下文信息
2. 指定技术实现要求
3. 生成后仔细审查
4. 充分测试各种场景
5. 有问题及时反馈给AI修改

## 三、总结

AI代码生成的核心要点：

1. **描述清晰**：需求越详细，生成的代码越准确
2. **小步快跑**：一次做一个功能，验证通过再做下一个
3. **及时反馈**：有问题马上告诉AI，让它调整
4. **善用参考**：提供PRD、现有代码作为参考
5. **充分测试**：生成后务必测试各种场景

记住：**AI是工具，你是产品经理+测试工程师。**
- 你负责想清楚要什么
- AI负责写代码
- 你负责验证对不对
