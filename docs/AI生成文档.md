# AI生成文档

> **完全没有文档的项目**
> 
> 如果你接手一个项目，只有代码，没有任何相关的说明文档，或者由于历史原因，导致项目缺少文档，这份文档就是为你准备的。
> 或者在某些场景下开发需求，文档是必须的，写文档又费时费力，这份文档也是为你准备的。
> 在AI时代，写技术文档不再需要记住复杂的格式规范。你只需要**用平常说话的方式**告诉AI你想做什么，AI就会帮你把文档写好。
> 
> 本文档将手把手教你：
> - 如何用"大白话"描述你想要的文档
> - 如何让AI帮你生成完整的技术文档
> - 如何结合现有代码反向生成文档

---

## 一、开发过程中生成文档

### 1.1 核心思路

**用自然语言描述你想要的文档，AI帮你写。**

你不需要懂文档规范，只需要清楚地告诉AI
- 你想要什么类型的文档
- 这个文档是给谁看的
- 文档需要包含哪些内容
- 期望的格式和风格

### 1.2 操作方法
  参考AI生成文档第二部分，将所需要的文档生成到 `docs/` 目录下。

### 1.3 审阅和完善

AI生成文档后：
1. 仔细阅读文档内容
2. 检查是否覆盖了所有需求
3. 如果有遗漏或不对的地方，告诉AI让它修改
4. 确认无误后保存到对应目录

## 二、根据现有项目生成文档

### 2.1 标准文档生成流程

按照软件工程规范，及日常需要让AI生成文档，生成对应的文档并保存到 `docs/` 目录

#### 第1步：需求功能清单

**提示词示例：**
```
你是有10年以上经验的全栈开发，根据当前项目信息，生成一份项目的功能清单Markdown，要求符合标准软件工程需求分析规范。
```
**保存文件：** `docs/功能需求清单.md`

#### 第2步：UI设计（原型交互设计文档）

**提示词示例：**
```
你是有10年以上经验的UI设计师，根据当前项目信息，及前端页面，生成一份项目的功能交互原型图 Markdown。要求包含垂直导航菜单和右侧工作区视图等，页面风格，并列出主要的交互跳转逻辑。
```
**保存文件：** `docs/frontend-ui.md`（交互设计文档）

#### 第3步：软件详细设计文档（PRD文档）

**提示词示例：**
```
你是有10年以上经验的全栈开发，阅读当前项目信息，生成一份项目的详细设计文档 Markdown。要求明确接口的非功能性、安全、兼容性设计，要符合标准软件需求规格说明书。文件为 "docs/PRD.md"
```
**保存文件：** `docs/PRD.md`（软件详细设计文档）

#### 第4步：数据库设计文档

**提示词示例：**
```
你是一个有10年以上经验的DBA专家。深入分析项目的数据库及项目运行的SQL，请编写数据库设计文档，并保存为 "docs/数据库设计文档.md"，包含数据库表结构、索引、约束、初始数据设计脚本，要求符合MySQL设计规范。
```
**保存文件：** `docs/数据库设计文档.md`（含 init.sql）

#### 第5步：接口设计文档

**提示词示例：**
```
你是一个有10年以上经验的全栈开发，阅读后端代码，统一整理API 接口定义，输出文件为 "docs/接口设计文档.md"
```
**保存文件：** `docs/接口设计文档.md`

#### 第6步：用户操作手册

**提示词示例：**
```
你是一个有10年以上经验的技术文档工程师。请为当前系统编写用户操作手册，面向最终用户（非技术人员），用大白话描述每个功能的操作步骤。文件为 "docs/用户操作手册.md"
```
**保存文件：** `docs/用户操作手册.md`

### 2.2 高效提问技巧

#### 技巧1：指定文档风格

```
帮我写一份数据库设计文档，要求
- 包含表结构定义（字段名、类型、注释、约束）
- 包含索引设计说明
- 包含外键关系图
- 包含初始数据脚本
- 符合MySQL 8.0设计规范
```

#### 技巧3：分步骤生成

对于复杂文档，可以分步骤让AI生成

```
第一步：帮我设计文档大纲结构
第二步：根据大纲填充每个章节的内容
第三步：补充示例和图表
第四步：审阅格式，确保一致性
```

### 2.3 文档审查要点

AI生成文档后，检查以下信息

#### PRD文档检查清单
- [ ] 是否包含业务背景和目标
- [ ] 是否明确目标用户和角色
- [ ] 功能模块是否完整
- [ ] 是否有权限矩阵
- [ ] 非功能性需求是否明确（性能、安全、兼容性）
- [ ] 是否有术语表

#### 接口文档检查清单
- [ ] 接口路径是否符合RESTful规范
- [ ] 请求参数是否完整（类型、必填、默认值）
- [ ] 响应示例是否正确
- [ ] 异常场景是否覆盖
- [ ] 认证方式是否说明
- [ ] 数据字典是否完整

#### 数据库设计检查清单
- [ ] 表名和字段名是否规范
- [ ] 字段类型是否合理
- [ ] 主键、外键、唯一约束是否定义
- [ ] 索引是否合理
- [ ] 注释是否完整
- [ ] 初始数据是否正确

### 2.4 最佳实践

#### 1. 利用现有代码
如果已有代码，可以让AI根据代码快速反向生成文档

```
请根据当前项目的代码结构，反向生成以下文档：
1. 功能清单
2. 接口设计文档
3. 数据库设计文档
4. 系统README说明
```

#### 2. 参考现有文档
让AI参考项目已有的文档风格：

```
请参考 docs/PRD.md 的风格和格式，
编写学员管理模块的详细PRD。
```

### 2.6 常见问题FAQ

**Q1：AI生成的文档和实际代码不一致怎么办？**
A：把代码文件提供给AI，让它根据实际代码重新生成或修正文档。

**Q2：文档格式不规范怎么办？**
A：在提示词中明确要求：
```
请严格按照Markdown格式输出，包含：
- 一级标题、二级标题、三级标题
- 表格使用标准Markdown语法
- 代码块使用 ``` 包裹
- 列表使用 - 或 1. 2. 3.
```

**Q3：如何保证生成文档的质量？**
A：
1. 提供详细的上下文信息
2. 指定文档规范和格式要求
3. 生成后仔细审阅
4. 有问题及时反馈给AI修改

## 三、总结

AI文档生成的核心要点：

1. **描述清晰**：需求越详细，生成的文档越准确
2. **小步快跑**：一次生成一个文档，确认后再做下一个
3. **及时反馈**：有问题马上告诉AI，让它调整
4. **善用参考**：提供现有代码、文档作为参考
5. **充分审阅**：生成后务必仔细检查

记住：**AI是工具，你是文档审核员。**
- 你负责想清楚要什么
- AI负责写文档
- 你负责验证对不对
